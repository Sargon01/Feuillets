# Contributing to Feuillets

Feuillets is a long-form writing plugin for Obsidian. The source is TypeScript, compiled and bundled to an unminified `main.js` for distribution.

The project favors **small, verifiable changes** over broad rewrites. Existing vaults and manuscripts are part of the public contract.

## Development setup

```bash
git clone https://github.com/Sargon01/Feuillets.git
cd Feuillets
npm install
npm run dev
```

`src/main.ts` is the application entry point. The root `main.js` is generated by the build and must not be edited as source.

For a development vault, link or copy the repository into:

```text
<vault>/.obsidian/plugins/feuillets/
```

Then build and reload Obsidian.

## Required checks

Before proposing a change, run:

```bash
npm test
npm run build
npm run lint
npm run lint:obsidian
```

Do not weaken a test, lint rule or Obsidian review configuration merely to make a change pass.

## Source layout

```text
src/
├── main.ts
├── api/
├── integrations/
├── i18n/
├── services/
├── settings/
├── ui/
├── utils/
└── views/
```

See [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) for current responsibilities.

## TypeScript

New source code belongs in `.ts` files.

Prefer explicit types at module boundaries and for data shared across services/views. Do not widen a value to `any` simply to silence a compiler error.

`src/types.d.ts` contains global project interfaces used across the codebase. Add fields only when they correspond to verified implementation state.

## User-facing text

The interface is bilingual.

Never introduce displayed text in only one language. Add matching keys to:

- `src/i18n/fr.ts`
- `src/i18n/en.ts`

then use `t("...")`.

Context-menu items, tooltips, placeholders, notices and conditional option labels are user-facing text too.

Internal identifiers, stored enum values, frontmatter keys and file-format markers are not translated just because the UI is.

## Compatibility rules

Existing vaults are part of the public contract.

In particular:

- never rename or move a user's files as a side effect of an update;
- recognize historical French/English folder names where current resolvers support them;
- keep old stored settings migratable when a setting changes;
- do not silently replace an existing project structure with the current preferred one;
- a folder used **as-is** must stay inside its own operational scope;
- changing a YAML mapping must not trigger a bulk property migration;
- linking an external Research folder must not move, copy or take ownership of that folder.

When a compatibility alias can be read indefinitely at low cost, reading it is generally safer than rewriting user data.

## Project roots and auxiliary folders

Do not assume every project is shaped as `<Project>/Manuscrit`.

Feuillets supports both a structured project and an arbitrary existing folder used directly as the manuscript.

New auxiliary material belongs under the canonical `_Feuillets` namespace when the corresponding service creates it, for example:

```text
_Feuillets/
├── Recherche/
├── Ressources/
├── Edition/
├── Journal/
├── Snapshots/
├── Backups/
└── Sortie/
```

Historical locations remain recognized where resolvers support them. Code must use the central folder/project helpers rather than reconstructing paths with `root.parent` or ad-hoc string rules.

## Frontmatter and YAML mapping

Do not reimplement YAML parsing or serialization with ad-hoc regular expressions.

Use `src/services/frontmatter.ts`, Obsidian frontmatter APIs and the existing project-mapping helpers.

The same rule applies to:

- title/short-title resolution;
- labels;
- frontmatter stripping;
- legacy aliases;
- logical mapped fields.

A feature that reads or writes a mappable logical field must not bypass the project mapping layer with a second private interpretation of YAML.

## Ordering

Binder order is explicit project state when available.

Use the existing ordered-children/order helpers. Natural sorting is a fallback, not a replacement for persisted manuscript order.

Imports that have a meaningful source order (for example Scrivener Binder order or an imported outline) must preserve that source order explicitly rather than relying on filename sorting.

## Binder and Continuous mode

The Binder is a high-risk integration surface because it coordinates navigation, selection, drag/drop, isolation and Continuous membership.

When changing split/single presentation, preserve the right-hand Binder's behavior unless the feature explicitly requires a Binder behavior change. A left navigation surface must not silently alter selection, isolation, compilation scope or Continuous membership.

Continuous mode edits the real source files through one composite editor. Do not introduce a generated composite manuscript file or a many-tabs simulation.

## Research and external folders

External Research associations are documentary links, not ownership transfers.

A linked outside folder may be displayed and navigated, but Feuillets must not offer destructive management of that folder from the linked-folder entry point unless an explicit product decision changes the contract.

Read-only vault browsing must likewise remain navigation-only and must not implicitly add outside files to Binder selection, Continuous mode or compilation.

## DOM and Obsidian review

Follow the rules enforced by `eslint-plugin-obsidianmd`.

In particular:

- prefer Obsidian DOM helpers in the live application document;
- do not use `innerHTML` for normal UI;
- keep static visual styling in `styles.css`;
- prefer classes/CSS variables for runtime visual state;
- keep unsupported/internal API use guarded and narrowly scoped.

Documented exceptions inside isolated print/iframe documents must not be copied into ordinary UI code.

## Platform behavior

`manifest.json` declares Feuillets as not desktop-only.

A genuinely desktop-only feature must detect the platform, stop before unavailable APIs and show a clear message.

PDF export uses the desktop system print flow. Scrivener import may require explicit desktop filesystem access according to the current importer; it must never scan arbitrary external locations in the background.

## Analysis companions

Feuillets exposes a text-analysis provider contract in `src/api/text-analysis.ts`.

The core plugin does **not** bundle a grammar engine or require a remote proofreading service. Companion providers remain separate software and returned ranges must be validated before use.

## Review features

Keep these concepts distinct:

- **working annotations**: personal, local, outside Markdown;
- **collaborative review**: `.feuillets` exchange and reviewer session;
- **DOCX Revision**: imported Word review;
- **comparison**: visual/decision layer used by several workflows.

Do not collapse their storage or lifecycle merely because they may share visual comparison components.

## Export

Reuse the existing composition/export pipeline. Do not create a second engine for a new button or command.

Output writing must remain safe when an existing file differs only by filename case on a case-insensitive filesystem.

## Documentation

A behavior change is incomplete when user documentation becomes false.

When relevant, update:

- `README.md` and `README-fr.md`;
- the functional guide concerned;
- `docs/FONCTIONNALITES.md` / `docs/FEATURES.md`;
- `docs/ARCHITECTURE.md` for structural changes;
- `PRIVACY.md` / `SECURITY.md` for data, network, filesystem or external-resource changes;
- `CHANGELOG.md` for release-visible changes.

Screenshots live once in `docs/`. Reuse their paths rather than duplicating image files.

See [`docs/NOTE-DE-MAINTENANCE.md`](docs/NOTE-DE-MAINTENANCE.md).

## Commits

Use focused commits with descriptive messages. Conventional prefixes such as `fix:`, `feat:`, `refactor:`, `docs:` and `chore:` are preferred.

Do not mix unrelated cleanup or architectural rewrites into a bug fix.

## Releases

Keep version metadata and changelog consistent, run the complete validation suite, and let the repository workflow build distributable artifacts.

Do not hand-edit generated production `main.js` as source.

## Reporting bugs

Please include:

- Feuillets version;
- Obsidian version;
- operating system;
- steps to reproduce;
- project shape (structured `Manuscrit` project or existing folder used as-is);
- relevant scope/view;
- export format/template when the issue concerns export.

A minimal reproducible vault structure is more useful than a screenshot alone.
