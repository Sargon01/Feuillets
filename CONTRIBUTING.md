# Contributing to Feuillets

Feuillets is a long-form writing plugin for Obsidian. The source is written in TypeScript, compiled and bundled to an unminified `main.js` for distribution.

The project favors **small, verifiable changes** over broad rewrites. Existing vaults and existing manuscripts must keep working.

## Development setup

```bash
git clone https://github.com/Sargon01/Feuillets.git
cd Feuillets
npm install
npm run dev
```

`src/main.ts` is the application entry point. The root `main.js` is generated by the build and is ignored by Git.

For a development vault, link or copy the repository into:

```text
<vault>/.obsidian/plugins/feuillets/
```

Then run the build and reload Obsidian.

## Required checks

Before proposing a change, run:

```bash
npm test
npm run build
npm run lint
npm run lint:obsidian
```

What these checks currently mean:

- `npm test` compiles the TypeScript test target and runs the Node test suite;
- `npm run build` runs TypeScript checking, then creates the production bundle with esbuild;
- `npm run lint` runs ESLint and TypeScript checking;
- `npm run lint:obsidian` runs the Obsidian review ESLint configuration against `src/`.

Do not reduce the number of tests to make a change pass.

## Source layout

The main areas are:

```text
src/
├── main.ts
├── api/
├── integrations/
├── i18n/
├── services/
├── settings/
├── ui/
├── utils/
└── views/
```

See [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) for the current responsibilities.

## TypeScript

New source code belongs in `.ts` files.

Prefer explicit types at module boundaries and for data shared across services/views. Avoid widening a value to `any` simply to silence a compiler error.

`src/types.d.ts` contains global project interfaces used across the codebase. Add fields there only when they are real, persisted or otherwise verified by the implementation.

## User-facing text

The interface is bilingual.

Never introduce a new displayed sentence in only one language. Add matching keys to:

- `src/i18n/fr.ts`
- `src/i18n/en.ts`

then use `t("...")`.

Internal identifiers, stored enum values, frontmatter keys and file-format markers are not translated just because the UI is.

## Compatibility rules

Existing vaults are part of the public contract.

In particular:

- never rename or move a user's files as a side effect of an update;
- recognize historical French and English folder names when the current code already supports them;
- keep old stored setting values migratable when a setting changes;
- do not silently replace an existing project structure with the current preferred structure;
- a folder used **as-is** must stay inside its own operational scope for output and backups.

When a compatibility alias can be read indefinitely at low cost, reading it is generally safer than rewriting user data.

## Project roots

Do not assume that every project is shaped as `<Project>/Manuscrit`.

Feuillets supports both:

```text
Project/
└── Manuscrit/
```

and an arbitrary folder used directly as the manuscript.

Code that writes `_Sortie`, `_Backups` or another technical folder must use the existing central helpers/rules rather than blindly using `root.parent`.

## Frontmatter

Do not reimplement YAML parsing or serialization with ad-hoc regular expressions.

Use the central helpers in `src/services/frontmatter.ts` and Obsidian's YAML facilities where appropriate.

The same rule applies to:

- label parsing;
- title resolution;
- frontmatter stripping;
- legacy field aliases.

## DOM and Obsidian review

Follow the rules enforced by `eslint-plugin-obsidianmd`.

In particular:

- prefer Obsidian DOM helpers (`createEl`, `createDiv`, `setIcon`, etc.) in the main Obsidian document;
- do not use `innerHTML` for live application UI;
- keep static visual styling in `styles.css`;
- when a value is computed at runtime, prefer CSS variables/classes over scattering inline application styles;
- use `window.setTimeout` / `window.setInterval` where the project already does so for pop-out-window compatibility;
- keep unsupported/internal API use guarded and narrowly scoped.

There are justified exceptions inside isolated print/iframe documents. Preserve the documented reasoning rather than copying those exceptions into normal UI code.

## Platform behavior

`manifest.json` declares Feuillets as not desktop-only, with Obsidian 1.13.0 as the minimum version.

A feature that is genuinely desktop-only must:

1. detect the platform;
2. stop before reaching an unavailable API;
3. show a clear user-facing message.

PDF export is currently desktop-only because it uses the system print dialog.

## Analysis companions

Feuillets contains a public text-analysis provider contract in `src/api/text-analysis.ts`.

The core plugin does **not** contain a grammar engine. Do not add a language engine or remote proofreading service directly to the core without an explicit product decision.

A companion provider must remain replaceable and its returned ranges must be validated before Feuillets uses them.

## Documentation

A behavior change is not complete when the user documentation becomes false.

When relevant, update:

- `README.md` and `README-fr.md`;
- the functional guide concerned;
- `docs/FONCTIONNALITES.md` / `docs/FEATURES.md`;
- `docs/ARCHITECTURE.md` for structural changes;
- `PRIVACY.md` / `SECURITY.md` for changes to data, network, filesystem or external-code behavior.

Screenshots live once in `docs/`. Reuse their paths rather than duplicating image files.

See [`docs/NOTE-DE-MAINTENANCE.md`](docs/NOTE-DE-MAINTENANCE.md).

## Commits

Use focused commits with descriptive messages. Conventional prefixes such as `fix:`, `feat:`, `refactor:`, `docs:` and `chore:` are preferred.

Do not mix an unrelated cleanup or architecture rewrite into a bug fix.

## Releases

Release automation lives in `.github/workflows/`.

When preparing a release, keep version metadata and the changelog consistent with the release being produced, run the complete validation suite, and let the repository workflow build the distributable artifacts.

Do not hand-edit the generated production `main.js` as source.

## Reporting bugs

Please include:

- Feuillets version;
- Obsidian version;
- operating system;
- steps to reproduce;
- whether the project is a structured `Manuscrit` project or an existing folder used as-is;
- export format/template when the problem concerns export.

A minimal reproducible vault structure is more useful than a screenshot alone.
